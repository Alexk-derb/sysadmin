# 0015: Персона в CLAUDE.md — вход «открыл папку → говоришь с сисадмином» (2.0)

**Статус:** Принято
**Дата:** 2026-06-13
**Автор:** Claude + решение оператора (этап 2 плана рефакторинга)

## Контекст

До 2.0 персона агента жила в `.claude/agents/sysadmin.md` как **субагент** — его
вызывали через `@sysadmin` или Task. Это ломало вход для новичка: «открыл папку и
пишешь» давало голого Claude, а не сисадмина; роль надо было явно звать.

Факты, выясненные исследованием реальных механизмов Claude Code (claude-code-guide):

- `"agent": "<name>"` в `.claude/settings.json` **реально** делает названного агента
  главным тредом сессии при открытии папки (применяет его system prompt и `tools:`).
- `CLAUDE.md` грузится как **user-message после system prompt** при каждом старте;
  документированный целевой размер — **до ~200 строк** для надёжного следования;
  слабее system-prompt, но всегда в контексте.
- **Главный агент имеет ВСЕ инструменты по умолчанию**, включая `Skill`. У субагента
  `sysadmin.md` в `tools:` был список `Bash, Read, Write, Edit, Glob, Grep` — **без
  `Skill`**, поэтому как субагент он не мог вызвать ни один из 20 скиллов.

Противоречие в плане рефакторинга: задача 2.1 предписывала «перенести персону в
CLAUDE.md и удалить/заглушить agent-файл», а задача 2.3 — «`settings.json agent:
sysadmin`» (которому agent-файл нужен). Оба сразу невозможны.

Рассмотрены три варианта:
- **(А) Персона → CLAUDE.md.** Вход — через загрузку CLAUDE.md при открытии папки.
- **(Б) Персона остаётся в agent-файле + `settings.json agent`.** Вход — через механизм
  главного-агента-по-имени (best practice по докам).
- **(В) Гибрид:** ядро конституции в CLAUDE.md (всегда-вкл) + полная персона в agent-файле.

## Решение

**Мы переносим персону в `CLAUDE.md`** (вариант А, выбран оператором). `CLAUDE.md`
становится носителем роли по умолчанию: открыл папку `sysadmin/` → Claude читает
CLAUDE.md → ведёт себя как сисадмин, с полным набором инструментов (включая `Skill`)
автоматически.

Структура после переноса:
- **`CLAUDE.md`** = персона сисадмина **на диете** (рефлекс = триггер + правило +
  указатель в `references/`; «почему/история/источники» — в `references/`) +
  универсальные правила (запрет на выдумки, секреты, формат коммитов), нужные в любом режиме.
- **DEV-правила** (синхрон слоёв персоны, «изменил скиллы → обнови доки», «документ без
  ссылки — неполная задача», ADR-дисциплина, карта репо) **переезжают в скилл `/dev`**
  (ADR не дублирует — см. задачу 2.2): открыл папку — ты сисадмин; правишь мозг — зовёшь `/dev`.
- **`.claude/agents/sysadmin.md`** → тонкая заглушка-указатель на CLAUDE.md (сохраняется
  для `@sysadmin` из чужих папок и discovery по `name`; не удаляется).
- **`settings.json agent: sysadmin` как механизм входа НЕ используется** — вход обеспечивает
  CLAUDE.md. Это резолвит противоречие 2.1/2.3 в пользу CLAUDE.md как единственного носителя.

## Последствия

- ✅ Новичок получает сисадмина сразу: «открыл папку и пишешь» работает без `@`-вызова.
- ✅ Скиллы заработали: главный агент имеет `Skill` по умолчанию (исчез баг «персона без Skill»).
- ✅ Один носитель персоны (CLAUDE.md), нет дубля «CLAUDE.md + agent system-prompt».
- ⚠️ CLAUDE.md грузится как user-message — следование слабее system-prompt; митигируется
  диетой (компактные формулировки, детали в `references/`) и тем, что конституция
  остаётся жёсткими NEVER-правилами.
- ⚠️ CLAUDE.md всегда в контексте, в т.ч. при разработке мозга — поэтому нужен `/dev`
  и предохранители «в роли сисадмина не правлю мозг → зову /dev» (задача 2.2/2.3).
- ⚠️ Бюджет CLAUDE.md критичен — лимит ядра теперь применяется к CLAUDE.md (в КБ,
  pre-commit `wc -c`); ADR-0002/0012 (cap «в строках» для agent-файла) пересматриваются
  задачей 2.4.
- ⚠️ Линтер `check-persona-sync.sh`, `cold-start.md` (§1 поиск персоны), `.githooks/pre-commit`
  переводятся с `sysadmin.md` на `CLAUDE.md`.
