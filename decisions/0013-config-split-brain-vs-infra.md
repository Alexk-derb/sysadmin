# 0013: Расщепление конфига — мозг агента (agent-config) отдельно от карты инфры (infra-config)

**Статус:** Принято
**Дата:** 2026-05-31
**Автор:** @sysadmin + Vasily

## Контекст

Что происходило, когда принималось это решение. Факты без оценок.

1. **Симптом.** На каждом холодном старте агент выполняет «поиск конфига» перебором
   по 6 типичным путям (`./`, `../infra/`, `~/infra/`, `~/work/infra/`,
   `~/projects/infra/`, `$INFRA_DIR`), плюс читает скрипт `find-config.sh`. Для
   оператора это выглядит как «агент каждый раз заново ищет, где живёт его
   собственная инфраструктура» — раздражающий ритуал, повторяющийся каждую сессию.

2. **Корневая причина — рекурсия «курица-яйцо».** Указатель на инфраструктуру
   (`infrastructure.root_path`) лежит ВНУТРИ файла `sysadmin-config.json`, который
   сам лежит ВНУТРИ папки `infra/`. Чтобы узнать, где инфра, надо открыть файл,
   который лежит в инфре, которую ещё не нашли. Поэтому — перебор.

3. **Расхождение замысла и реализации.** ADR-0018 (инфра) п.6 решал: «Личный
   `sysadmin-config.json` живёт в `sysadmin/`, не в infra/. Агент читает конфиг из
   `sysadmin/` (это его дом), оттуда берёт путь к infra/». По факту конфиг уехал
   в `infra/` — `/sysadmin-init` кладёт его внутрь папки инфры (зафиксировано в
   ADR-0008 инфры и в `find-config.sh`). «Дом агента» в `sysadmin/` опустел.

4. **Две сущности слиплись в одном файле.** Текущий `sysadmin-config.json` смешивает:
   - **агент-центричное** (как агент общается с оператором): `language`,
     `operator`, `secrets.manager`, `meta.onboarding`;
   - **инфра-центричное** (описание сервера): `servers`, `monitoring`, `backups`,
     `notifications`, `vpn`, `infrastructure.root_path`.
   Имя файла («sysadmin-config») при этом притворяется и паспортом агента, и
   картой инфры одновременно. Само имя вводит в заблуждение: файл лежит в данных,
   но назван по агенту.

5. **Запрос на несколько инфраструктур.** Оператор сформулировал сценарий: у него
   может быть несколько проектов — «инфра одного сервера в `infra-1/`, отдельный
   рабочий проект в `infra-2/`». Мозг агента должен знать про все проекты и где
   каждый живёт. Текущая схема держит `infrastructure.root_path` как одно
   значение (не массив). ADR-0017 (инфра) альтернатива 4 «множественность
   конфигов» была отвергнута «до реальной потребности» — потребность наступила.

6. **Модель оператора (его формулировка, 2026-05-31).** Три сущности:
   - конфиг **мозгов** агента — живёт в `sysadmin/`, отвечает за самого агента
     (кто оператор, язык, какие проекты есть, режимы взаимодействия);
   - конфиг **инфраструктуры** = «оглавление / Table of Contents» — живёт в
     `infra/`, карта-указатель «нужно про VPN → сюда, про сайт → сюда»;
   - сами **данные** — `inventory/`, `knowledge/`, `decisions/`, на которые
     указывает оглавление.

7. **Существующие ограничения.** `find-config.sh` используют 12 скиллов (через
   `find_sysadmin_config`, `resolve_infra_path`, `get_config_field`,
   `require_config_field`). Персона двухслойна (выжимка `sysadmin.md` + полный
   слой `references/cold-start.md`), синхронность защищена линтером
   `check-persona-sync.sh` и pre-commit hook. Любая правка ядра обязана пройти
   линтер.

## Решение

Мы расщепляем единый конфиг на **два файла с разной ответственностью** и
восстанавливаем «дом агента» в `sysadmin/`.

### 1. Три сущности, три места

```
sysadmin/                       ← МОЗГ агента (ПУБЛИЧНЫЙ репо → GitHub)
  agent-config.example.json     ← публичный шаблон. Коммитится. Обезличен.
  agent-config.schema.json      ← публичный контракт. Коммитится.
  agent-config.json             ← ЛИЧНЫЙ. В .gitignore. НЕ уезжает в GitHub.

infra/  (любой проект)          ← ДАННЫЕ оператора (ПРИВАТНЫЙ репо)
  infra-config.example.json     ← публичный шаблон (в sysadmin/ тоже копия)
  infra-config.schema.json      ← публичный контракт (в sysadmin/ тоже копия)
  infra-config.json             ← ЛИЧНЫЙ. В .gitignore приватного репо.
  inventory/ knowledge/ decisions/   ← данные, на которые указывает карта
```

**Граница «GitHub vs .gitignore» (критично — публичный продукт):**

| Артефакт | Где | В GitHub? |
|---|---|---|
| `agent-config.schema.json`, `agent-config.example.json` | `sysadmin/` | ✅ да (обезличены) |
| `infra-config.schema.json`, `infra-config.example.json` | `sysadmin/` + `infra/` | ✅ да (обезличены) |
| `agent-config.json` (личный паспорт мозгов) | `sysadmin/` | ❌ **.gitignore** |
| `infra-config.json` (личная карта инфры) | `infra/` | ❌ .gitignore |

Личный `agent-config.json` содержит имя оператора, реальные пути к его проектам,
менеджер паролей — это персональные данные, они **обязаны** быть в `.gitignore`
публичного репо (первым правилом, как сейчас сделано для `sysadmin-config.json`).
Ученик, клонировав репо, получает только schema + example и заполняет свой личный
конфиг через `/sysadmin-init`.

### 2. `agent-config.json` (мозг) — содержит

- `operator` — имя, язык, таймзона, менеджер паролей (всё агент-центричное, что
  сейчас не по месту лежит в инфра-конфиге);
- `projects[]` — **реестр проектов** (массив сразу): для каждого `id`, `title`,
  `infra_root` (путь к папке проекта), `config` (путь к его `infra-config.json`);
- `default_project` — какой проект активен по умолчанию;
- `interaction` — режимы взаимодействия (уровень подтверждений, предпочтения
  стиля) — наполняется по мере необходимости, начинаем с минимума;
- `meta.onboarding` — переезжает сюда из инфра-конфига.

### 3. `infra-config.json` (карта инфры) — содержит

- инфра-поля как сейчас: `servers`, `monitoring`, `backups`, `notifications`,
  `vpn`;
- БЕЗ агент-полей (`language`, `operator`, `secrets` уезжают в `agent-config`);
- БЕЗ `infrastructure.root_path` (он больше не нужен — путь к самой папке теперь
  знает реестр `projects[]` в мозге);
- опциональный блок `map` — указатели вглубь данных («vpn →
  inventory/hosts/.../vpn-3xui.md»), чтобы оглавление читалось «одним взглядом».

### 4. Новый Cold Start (Шаг 0)

1. Читаю `sysadmin/agent-config.json` напрямую → сразу знаю оператора, язык,
   список проектов. **Без перебора.**
2. Беру `default_project` → его `infra_root` и `config`.
3. Читаю `infra-config.json` (оглавление) → знаю серверы и куда смотреть.
4. Перебор по путям остаётся **только fallback** на случай, когда
   `agent-config.json` нет (новый пользователь, первый запуск) — публичный
   продукт должен работать «из коробки».

### 5. Отношение к прошлым ADR

- **Восстанавливает** изначальный замысел ADR-0018 п.6 («дом агента в
  `sysadmin/`»), который реализация нарушила.
- **Заменяет** ADR-0017 альтернативу 4 (множественность конфигов «отложена»):
  реестр `projects[]` вводится сейчас.
- **Отменяет** канон ADR-0008 (инфра) в части «`root_path` резолвится от каталога
  конфига» — поле `root_path` упраздняется; `infra_root` в реестре хранится
  абсолютным. Резолвер относительных путей остаётся как fallback-совместимость.

## Последствия

- ✅ **Старт без поиска.** Агент читает один известный файл и сразу знает всё.
  Ритуал перебора исчезает для настроенного оператора.
- ✅ **Чистая граница.** Мозг (как агент работает) и данные (что на сервере) —
  физически разные файлы с честными именами. Имя `infra-config.json` больше не
  врёт.
- ✅ **Несколько проектов из коробки.** Реестр `projects[]` + `default_project`
  закрывают сценарий «infra-1 / infra-2».
- ✅ **Безопасность публикации сохранена.** Личные `agent-config.json` и
  `infra-config.json` — в `.gitignore`; в GitHub уезжают только обезличенные
  `*.example.json` + `*.schema.json`. Ученик клонирует шаблоны, заполняет личное
  через `/sysadmin-init`. Граница «публичное/личное» не размывается расщеплением.
- ✅ **Совместимость со старым.** Перебор-fallback и алиас старого имени функции
  не ломают существующие установки и публичный сценарий первого запуска.
- ⚠️ **Объём правок.** Затрагивает 2 схемы, 2 шаблона, `find-config.sh`, ядро
  двухслойной персоны (под линтером), `/sysadmin-init`, 12 скиллов, документацию.
  Mitigation: поэтапный план снизу вверх (фундамент → ядро → потребители), на
  каждом шаге система рабочая; старое имя функции — алиас на переходный период.
- ⚠️ **Миграция существующих установок.** У оператора (и у учеников) уже есть
  `sysadmin-config.json` в infra/. Нужен путь миграции: расщепить на два файла,
  старый → `.bak`. Mitigation: `/sysadmin-init` детектит старый формат и
  предлагает миграцию; ручной разрез для оператора в Этапе 7.
- ⚠️ **Риск рассинхрона персоны.** Правка Cold Start трогает оба слоя. Mitigation:
  линтер `check-persona-sync.sh` + pre-commit hook (обязательный PASS).
