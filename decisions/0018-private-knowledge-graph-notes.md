# 0018: Приватный knowledge — граф атомарных заметок вместо монофайлов-журналов

**Статус:** Принято
**Дата:** 2026-07-03
**Автор:** Claude (Fable 5) + согласовано с Василием

## Контекст

Приватная память агента (`$INFRA/knowledge/`) хранит уроки и процессные паттерны
в монолитных файлах-журналах, и они упёрлись в собственную механику:

- `lessons-learned.md` — 574 строки, **35 уроков в одном файле** (первичная оценка «38»
  по `grep -c "^## "` завышена: grep считал и заголовки-шаблоны внутри code-fence),
  вручную сгруппированы в 10 тематических разделов. Чтобы достать один урок про
  Docker-сети, агент читает всю простыню; связи между уроками существуют только «в голове».
- `working-patterns.md` — **300 строк при потолке 200: потолок уже нарушен**, и это
  прошло незамеченным — сама конструкция потолка не самопроверяется.
- Хардовые потолки (≤1000 / ≤200 строк, §5 ядра) — костыль именно от монолитности:
  ритуал «на финише `wc -l`, при превышении сначала сжатие отдельным коммитом» — это
  ручная борьба с ростом файла, а не со структурой знания. Одно сжатие уже случилось
  (архив `lessons-learned-archive-2026-04.md`), потребовало отдельной сессии.

Рядом существуют два образца устройства «мозгов» на графе markdown-заметок:

- **bb** (`../bb/`, агент-эксперт по бодибилдингу, 213 заметок) — обкатанный стандарт
  `docs/knowledge-standard-core.md`: атомарная заметка = сущность, YAML-frontmatter,
  `[[wiki-ссылки]]`, MOC, слой доверия (провенанс, `consensus`, `reliability` A/B/C/F,
  верификация источников).
- **loreground** (`../loreground/`, greenfield) — замысел вынести это ядро в переносимый
  публичный стандарт.

Разбор от 2026-07-03 (по вопросу оператора «не организовать ли мозги агента так же»)
показал: мозг — не одно хранилище, а **пять слоёв** с разными режимами чтения, и граф
уместен не везде:

1. **Ядро персоны** (`CLAUDE.md` + references) — грузится целиком каждую сессию;
   граф противопоказан: конституция не может быть «заметкой, найденной по релевантности».
2. **Доменный knowledge** (`.claude/knowledge/networking/`) — **уже граф** (frontmatter,
   слои TTL, реестр источников; ADR-0006).
3. **Приватный knowledge** (`$INFRA/knowledge/`) — монолиты, боль живёт здесь.
4. **Инвентарь** (`$INFRA/inventory/`) — уже «одна сущность = один файл».
5. **Авто-память** (`~/.claude/projects/<slug>/memory/`) — уже заметки с frontmatter,
   `[[бэклинками]]` и индексом `MEMORY.md`.

Рассматривался и полный перенос стандарта bb, включая слой доверия — отвергнут:
ценность слоя доверия bb в доказательстве внешних фактов наукой (консенсус ≥2 типов
источников, верификация через PubMed). Источник истины сисадмина — сам сервер
(`docker ps`, конфиг), «контейнер запущен» не доказывают консенсусом, а проверяют
командой; ось доверия агента уже встроена в §4.6 («по памяти, проверю» vs
«свершившийся факт»). Там, где агент опирается на внешние факты (networking), аналог
слоя доверия уже введён ADR-0006 (`sources_checked`, реестр, порог HIGH/MEDIUM).

## Решение

Мы переводим **только слой 3** — уроки и паттерны приватного knowledge — на граф
атомарных заметок, беря из стандарта bb **скелет навигации** (атомарность, frontmatter,
бэклинки, индекс-MOC) и осознанно **не беря** слой доверия (провенанс-заметки,
`consensus`/`reliability`, верификацию источников).

### Целевая структура `$INFRA/knowledge/`

```
knowledge/
  00-index.md            # Home-MOC: одна строка на заметку, группировка по domain
  README.md              # 5 строк: что это за папка → указатель на 00-index.md
  lessons/               # уроки: 1 урок = 1 заметка
    certbot-deploy-hook.md
    …
  patterns/              # процессные паттерны: 1 паттерн = 1 заметка
    commits-russian-format.md
    …
  _templates/            # шаблоны заметок (lesson.md, pattern.md)
  operator-profile.md    # остаётся файлом: одна сущность — оператор
  <справочники>.md       # docker-best-practices и т.п. — остаются: каждый = одна тема
  troubleshooting/       # остаётся
  lessons-learned-archive-2026-04.md  # архив прошлого сжатия — остаётся как есть
```

### Схема frontmatter заметки

```yaml
---
title: certbot — обновление в live/ не доходит до nginx без deploy-hook
type: lesson            # lesson | pattern
domain: tls             # tls | network | docker | postgres | nginx | git-deploy |
                        # secrets | ssh-remote | hygiene | process
date: 2026-04-20        # когда усвоен/закреплён
status: active          # active | superseded (+ строка "superseded by [[...]]" в теле)
related: ["[[tls-check-all-acme-clients]]"]   # опционально
source: "инцидент / коммит / сессия"           # опционально, свободный текст
---
```

Ключи — EN; значения `domain` — технические термины как есть (EN), `title` — по-русски.
Поля доверия (`severity`, `consensus`, `reliability`) **не вводим**: оценку серьёзности
задним числом пришлось бы выдумывать (конфликт с C.2), а слой доверия не нужен (см. Контекст).

### Именование файлов — осознанное отступление от bb

bb именует файлы человекочитаемым русским `title`. Мы используем **латинский kebab-case
слаг** (`certbot-deploy-hook.md`), русский `title` — в frontmatter. Причина: контекст
сисадмина — терминал, SSH, bash-скрипты; латинские имена не требуют экранирования и
согласуются с существующим именованием в `infra/` (`docker-best-practices.md`).
`[[wiki-ссылки]]` указывают на имя файла без расширения. Правило bb §6.3 сохраняется:
файловые инструменты не обновляют бэклинки при rename → переименовывать редко, при
переименовании `grep "\[\[старый-слаг\]\]"` по knowledge/ и чинить все ссылки.

### Ритуал памяти (замена потолков)

- **Старт нетривиальной задачи:** читать `00-index.md` (+ `operator-profile.md`),
  релевантные заметки — точечно по индексу/grep, а не журнал целиком.
- **Финиш:** новый урок/паттерн = новая заметка по шаблону + **строка в `00-index.md`
  в том же коммите** (заметка без строки в индексе = потеряна) + `[[связи]]` с
  родственными заметками.
- **Потолки строк на журнал упраздняются.** Вместо них: ≤ ~80 строк на заметку
  (иначе это не атом — дели), `operator-profile.md` ≤200 как раньше.
- **Проверка на финише:** `bash $SYSADMIN_ROOT/scripts/validate-private-knowledge.sh
  $INFRA/knowledge` — frontmatter-ключи, битые `[[ссылки]]`, сироты (заметка есть —
  строки в индексе нет, и наоборот). Заменяет ритуал `wc -l`.
- Правки только приватные: заметки живут в `infra/` (приватный репо), в публичный
  `sysadmin/` не попадают — политика приватности не меняется.

### Миграция

Разовая, батч-скриптом (по образцу миграции 119 заметок в bb): 35 уроков из
`lessons-learned.md` + 13 паттернов из `working-patterns.md` → 48 заметок, тела
переносятся дословно (C.2 — ничего не выдумывать, `domain` берётся из существующей
рубрикации разделов, `date` из заголовков). Монофайлы после миграции удаляются из
`infra/` git-коммитом (история сохраняет их полностью; архив-2026-04 не трогаем).
Выполняется в роли сисадмина (это данные оператора, не мозг), по явному решению
оператора от 2026-07-03.

## Последствия

- ✅ Поиск урока = grep по `domain:`/тексту → чтение 1–3 атомарных заметок вместо
  574-строчного журнала; связи между уроками явные (`related`/`[[ссылки]]`).
- ✅ Потолок-костыль и ритуал «сжатие перед записью» исчезают: рост = новые файлы,
  а не распухание одного; периодические сессии сжатия больше не нужны.
- ✅ Cold Start Шаг 3 дешевеет по контексту: индекс (~60 строк) вместо трёх файлов
  (~1000 строк суммарно).
- ✅ Слои памяти 2, 3 и 5 теперь устроены единообразно (frontmatter + связи + индекс).
- ⚠️ Больше файлов (≈50 вместо 2) — навигация человеком глазами чуть тяжелее;
  компенсируется индексом и `Glob lessons/*.md`.
- ⚠️ Дисциплина индекса: заметка без строки в `00-index.md` потеряна для старта задачи;
  прикрыто валидатором (сироты) в ритуале финиша.
- ⚠️ Бэклинки при rename не обновляются сами (нет Obsidian) — правило «переименовывать
  редко + grep по ссылкам» перенесено из bb §6.3.
- ⚠️ Разовая стоимость миграции 49 заметок + правка всех точек касания персоны
  (§4.5, §5, §7.1, §8.2 ядра; memory-ritual; cold-start; retro; README).

## Связанное

- ADR-0006 (слоистая архитектура VPN-knowledge) — граф-подход слоя 2, образец «frontmatter
  + валидатор + свежесть»; ADR-0018 делает то же для слоя 3, но без оси источников.
- ADR-0016 (бюджет ядра) — правки §5 ядра в рамках бюджета 42 000 Б.
- ADR-0013 (расщепление конфига) — граница «мозг публичный / данные приватные»:
  стандарт и валидатор живут в `sysadmin/`, сами заметки — в `infra/`.
- Образец: `../bb/docs/knowledge-standard-core.md` (schema 1.0) и замысел `../loreground/`.
- Влияет на: `CLAUDE.md` §4.5/§5/§7.1/§8.2, `references/memory-ritual.md`,
  `references/cold-start.md`, скилл `/retro`, `README.md`,
  `scripts/validate-private-knowledge.sh` (новый), `$INFRA/knowledge/` (миграция).
