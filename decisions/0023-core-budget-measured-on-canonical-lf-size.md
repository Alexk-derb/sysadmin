# 0023: Бюджет ядра меряется каноническим (LF) размером, а не `wc -c` рабочей копии

**Статус:** Принято
**Дата:** 2026-07-27
**Автор:** режим `/dev` по итогам находки в сессии диагностики Codex

## Контекст

1. **ADR-0016 обосновал байтовую меру утверждением, которое оказалось неверным:** «байты
   (`wc -c`) меряются детерминированно и **кроссплатформенно**». Кроссплатформенности нет.

2. **Факт, вскрывший расхождение.** Один и тот же коммит `a8cefce`, две машины:

   | где | `wc -c CLAUDE.md` | остаток до 42 000 |
   |---|---|---|
   | ноутбук (Windows, рабочая копия с CRLF) | 41 986 | 14 Б |
   | сервер (Linux, рабочая копия с LF) | 41 572 | 428 Б |
   | объект в git (`git cat-file -s HEAD:CLAUDE.md`) | 41 572 | 428 Б |

   Разница ровно 414 байт — число строк файла: на Windows `core.autocrlf` разворачивает
   каждый `\n` в `\r\n` при checkout.

3. **`.gitattributes` эту дыру не закрывает.** Он нормализует `*.sh`, `*.bash`, `*.py`
   (заведён после аудита 2026-07-03, когда CRLF ломал скрипты на сервере), но `*.md` под
   нормализацию не попадает — а ядро персоны это именно markdown.

4. **Практические последствия расхождения.** Порог зависит от машины: правка, спокойно
   прошедшая pre-commit на сервере, блокируется на ноутбуке. Обратная сторона хуже —
   при правках на Linux ядро могло тихо перерасти задуманный вес почти на полкилобайта,
   и анти-храповик ADR-0016 считался бы соблюдённым.

5. Рассматривался вариант «добавить `*.md text eol=lf` в `.gitattributes`» — отвергнут как
   единственная мера: он чинит будущие checkout'ы, но не саму метрику (`wc -c` рабочей копии
   останется платформозависимым, а существующие клоны — с CRLF до пересборки рабочего дерева).

## Решение

**Мы меряем бюджет ядра каноническим размером — тем, что хранится в git (LF), а не размером
рабочей копии.**

- **В pre-commit** — `git cat-file -s :CLAUDE.md`: это ровно тот объект, который уйдёт в
  коммит, уже после clean-фильтра. Fallback, если git недоступен: `tr -d '\r' < CLAUDE.md | wc -c`.
- **В скилле `/dev`** (показ бюджета первой строкой) — `tr -d '\r' < CLAUDE.md | wc -c`,
  потому что там файл может быть ещё не staged.
- **Бюджет остаётся 42 000 байт.** Число не меняется — меняется способ его измерения.

Отдельно фиксируем: переход к канонической мере **не является повышением cap**. Репозиторий
всегда хранил 41 572 байта; лишние 414 были свойством рабочей копии Windows, а не содержимым
ядра. Анти-храповик ADR-0016 действует без изменений — поднять 42 000 по-прежнему можно только
новым ADR.

## Последствия

- ✅ Порог одинаков на всех машинах: одна и та же правка либо проходит везде, либо нигде.
- ✅ Меряется то, что реально коммитится, а не артефакт checkout'а.
- ✅ Устранён сценарий тихого перерастания ядра при правках с Linux-машины.
- ⚠️ На Windows показатель разом «улучшился» с 41 986 до 41 572 (остаток 14 → 428 Б). Это не
  освободившееся место под новые блоки, а исправленный счётчик: правило «одно входит — одно
  выходит» действует ровно как прежде.
- ⚠️ Основной путь измерения теперь зависит от git (`cat-file`); для окружений без него
  оставлен fallback на `tr -d '\r'`.
- ⚠️ Ядро всё ещё близко к потолку (41 572 из 42 000). Разгрузка остаётся отдельной задачей,
  и этот ADR её не отменяет — он лишь убирает ложную срочность, созданную неверным счётчиком.

## Связанное

- Уточняет ADR-0016 (бюджет ядра в байтах + анти-храповик): единица меры уточнена, сам
  бюджет и механизм анти-храповика сохранены. В ADR-0016 проставлен статус «частично заменён»
  и врезка-поправка над опровергнутым утверждением о кроссплатформенности `wc -c` — иначе два
  действующих ADR противоречили бы друг другу, и читатель первого не узнал бы о втором.
- Связан с ADR-0015 (ядро персоны живёт в `CLAUDE.md`).
- Влияет на: `.githooks/pre-commit` (проверка бюджета), `.claude/skills/dev/SKILL.md`
  (показ бюджета и раздел «5. Бюджет ядра»).
