# 0021: Долгоживущие секреты передавать мимо контекста агента, а не через чат

**Статус:** Принято
**Дата:** 2026-07-23
**Автор:** оператор + агент (по итогам внешнего ревью Codex)

## Контекст

При настройке третьей (облачной) копии бэкапа RoboAcademy агент попросил оператора прислать
в чат два статических S3-ключа (Key ID + Secret), чтобы записать их в конфиг `rclone` на сервере.

Формально это не нарушало конституцию: **C.10** прямо разрешает приём секрета, введённого
оператором напрямую в приватной сессии, — «штатный рабочий канал, не компрометация».

Оператор запросил независимое мнение (Codex CLI). Вердикт внешнего ревьюера — не слать:

- переписка сохраняется в **транскрипт на диске открытым текстом**;
- содержимое сессии уходит в API **как контекст при каждой последующей реплике**, то есть один
  вставленный секрет многократно пересылается;
- в этом же репозитории есть скилл **`/retro`, который читает транскрипты прошлых сессий**, —
  поверхность утечки шире, чем «один приватный диалог»;
- ключи **долгоживущие**, сами не истекают: одна утечка тянется до ручной ротации;
- права `0600` на конечном файле защищают результат, но **не этап передачи**.

Существовал строго лучший путь, который агент не предложил сразу: оператор вводит секрет
**прямо на целевой машине** скрытым вводом (`read -s`), значение идёт из менеджера паролей на
хост, минуя контекст агента, историю команд и список процессов. В инциденте он и был применён
(скрипт `setup-yos-creds.sh`); ключи в чат так и не попали, ротация не потребовалась.

Рассматривался альтернативный вариант — передать агенту `BW_SESSION`-токен Bitwarden, чтобы он
достал секреты сам. Отклонён: токен открывает **всё** хранилище и сам является секретом в
транскрипте, то есть радиус поражения шире, а не уже.

## Решение

Мы дополняем **C.10** оговоркой: приём секрета из прямой сессии остаётся штатным каналом и НЕ
считается компрометацией (это не меняется), **но «не компрометация» ≠ «оптимальный способ»**.

Для **долгоживущих** секретов (ключи доступа, пароли БД, токены без срока) агент **сначала
предлагает путь мимо своего контекста** — ввод оператором непосредственно на целевой машине
скрытым вводом либо доставку из менеджера паролей на хост, — и только если оператор осознанно
выбирает иначе, принимает значение в сессии.

Правило про **короткоживущие/одноразовые** секреты (одноразовый код, временный токен, значение,
которое всё равно немедленно ротируется) не ужесточается: там чат остаётся приемлемым.

Полная таблица «канал → как поступаю» и процедура вынесены в
`.claude/agents/references/trust-zones.md` (раздел C.10) — заодно закрыт битый указатель:
ядро на эту таблицу ссылалось, а раздела в reference не существовало.

## Последствия

- ✅ Долгоживущие секреты перестают оседать в транскрипте и переставать пересылаться в контексте
  каждой реплики — сужается поверхность утечки, включая чтение транскриптов через `/retro`.
- ✅ Ротация после штатной работы по-прежнему не требуется — C.10 не превращается в запрет,
  меняется только предпочитаемый способ.
- ✅ Починен рассинхрон двухслойной персоны: у C.10 появился полный слой в `references/`.
- ⚠️ Оператору чуть больше работы: вместо «вставить в чат» — выполнить одну команду на сервере.
  Компенсируется тем, что агент готовит скрипт со скрытым вводом заранее.
- ⚠️ Появляется развилка «долгоживущий или одноразовый секрет» — агент обязан её проговаривать,
  иначе правило превратится в формальность.
