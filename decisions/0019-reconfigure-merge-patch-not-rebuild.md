# 0019: /sysadmin-init --reconfigure — merge-patch поверх текущего конфига, не пересборка из skeleton

**Статус:** Принято
**Дата:** 2026-06-29
**Автор:** @sysadmin (режим /dev)

## Контекст

`/sysadmin-init` в режиме `--reconfigure` после всех раундов шёл по тем же Шагам 8→9→10, что и
первичный setup: `scripts/assemble-configs.sh` **копирует skeleton** и заполняет `projects[0]` /
`servers[0]` из ответов интервью.

- assemble рассчитан на v1.0: **один проект, один сервер**. На reconfigure он пересобирает оба
  конфига с нуля и **теряет всё, что не пересоздаёт явно**: доп. проекты в мозге (`projects[1+]`),
  доп. серверы (`servers[1+]`), опц. блоки карты, не переданные флагами (`vpn`, `map`), блок `meta`.
- Баг всплыл при включении `backups.enabled=true` для `srv-spb-selectel` (ADR-0018): в мозге
  оператора **два проекта** (`srv-spb-selectel` + `iiservertim`), в карте srv-spb — заполненный
  блок `vpn`. Полная пересборка затёрла бы второй проект и блок vpn.
- Обходным путём флаг включили **точечным jq-патчем** текущей карты (backup → jq → валидация →
  write), руками. SKILL.md при этом обещал «НЕ затираю meta/VPN-поля — переношу в draft», но
  механизм (assemble из skeleton) этого не делал — документация расходилась с реальностью.

## Решение

Мы делаем запись в режиме `--reconfigure` **точечным merge-patch'ем поверх ТЕКУЩЕГО конфига**,
а не пересборкой из skeleton. Изменённые ключи накатываются jq-фильтром через новый
`scripts/reconfigure-write.sh` (backup → jq-патч → штатная валидация `validate-config.sh` →
write или громкий откат, C.9). Всё нетронутое сохраняется автоматически.

`assemble-configs.sh` остаётся **только для первичного setup**. Полноценный array-safe rebuild
(многопроектный/многосерверный) в assemble не делаем — для reconfigure он не нужен, патч точнее.

## Последствия

- ✅ reconfigure больше не теряет доп. проекты/серверы и опц. блоки (`vpn`/`map`/`meta`).
- ✅ Безопасно для мульти-проектных мозгов (реестр `projects[]` сохраняется целиком).
- ✅ Переиспользуется штатный `validate-config.sh` (явные `--agent`/`--infra`) + `.bak` + откат.
- ✅ Документация SKILL.md теперь совпадает с механизмом (обещание «не затираю» обеспечено делом).
- ⚠️ Два пути записи: `assemble-configs.sh` (setup) и `reconfigure-write.sh` (reconfigure) —
  это осознанное разделение, отражено в SKILL.md §«Режим --reconfigure».
- ⚠️ jq-fallback валидатора (когда нет `check-jsonschema`) проверяет лишь обязательные поля и
  `*.enabled`, но НЕ enum'ы/allOf — глубокую проверку даёт только установленный `check-jsonschema`
  (известное ограничение, не вводится этим ADR).

## Связанное

- Связан с ADR-0013 (расщепление конфига: мозг vs карта) и ADR-0018 (правка, на которой баг всплыл).
- Влияет на: `.claude/skills/sysadmin-init/SKILL.md` (§«Режим --reconfigure»),
  `scripts/reconfigure-write.sh` (новый), `scripts/assemble-configs.sh` (теперь только setup).
