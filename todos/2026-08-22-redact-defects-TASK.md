# Задание: маскировщик секретов `redact.sh` пропускает секреты и уничтожает данные

**Дата постановки:** 2026-08-22
**Ревизия, на которой всё измерено:** `b56f931`
**Режим:** `/dev` — правится мозг агента (`.claude/skills/_lib/`), на серверы не выходим.
**Как найдено:** слепая сверка двумя моделями (свежий Claude и Codex) по одному брифу,
материалы — `~/codex-research/2026-08-22-blind-trial/`.

---

## 1. Что это за код и почему это не косметика

`.claude/skills/_lib/redact.sh` — единственный рубеж маскировки для снимков инфраструктуры.
Через него проходит **каждая секция** `dump-snapshot.sh` (см. его строки 170-225), а снимки
затем **коммитятся в git**. Отсюда две цены ошибки, и обе тяжёлые:

- **пропустил секрет** → пароль, токен или приватный ключ уезжает в историю репозитория
  открытым текстом; удалить его оттуда потом нельзя, только ротировать сам секрет;
- **замаскировал лишнее** → снимок становится **ложным**, а по §4.6 персоны снимок считается
  источником истины. Агент читает искажённый инвентарь и принимает по нему решения.

Второе опаснее и обнаруживается позже: утечку ловит `gitleaks`, а стёртый инвентарь не ловит
никто.

## 2. Главное, что нужно знать перед началом

**`tests/test-redact.sh` — 19 тестов, прогон зелёный.** При восьми подтверждённых дефектах.
Набор проверяет то, что уже чинили (JWT, `sb_secret_`, отсутствие `jq`), и ни одного из дефектов
ниже не ловит. Считать его свидетельством исправности нельзя — это ровно тот класс «ложного
зелёного», ради которого заведено правило про приманку.

Первое, что стоит сделать, — **дописать в набор падающие тесты на все восемь дефектов** и
убедиться, что он краснеет. Чинить то, что не краснеет, бессмысленно: неизвестно, починилось ли.

## 3. Подтверждённые дефекты

Все воспроизведены замером на ревизии `b56f931`. Команды даны так, чтобы их можно было
выполнить сразу: сначала `. .claude/skills/_lib/redact.sh`, затем строка ниже.

### Класс A — секрет уходит наружу

**A1. Значение обрывается на пробеле, запятой, кавычке — хвост утекает.**

```sh
printf '%s\n' 'password: hunter2 correct horse battery' \
              'DB_PASSWORD="my secret pass phrase"' \
              'POSTGRES_PASSWORD=p4ss,w0rd,tail' | redact_stream
```

Наблюдалось: `password: <REDACTED> correct horse battery`,
`DB_PASSWORD="<REDACTED> secret pass phrase"`, `POSTGRES_PASSWORD=<REDACTED>,w0rd,tail`.
Причина — класс значения `[^"[:space:],}]+` в правиле 1 (строка ~49). Сюда же относится
многострочный YAML-блок: маскируется знак `|`, а тело блока уходит целиком — это и есть тот
случай, из-за которого в прошлом утёк `sb_secret_`.

**A2. Непрозрачные токены не покрыты вовсе.**

```sh
printf '%s\n' 'Authorization: Bearer ghp_16CharsAndMoreRealGitHubToken0000' | redact_stream
```

Наблюдалось: строка вышла без изменений. Правило 7 требует форму JWT (`eyJ….eyJ…`), а слово
`Authorization` под секрет-слова правила 1 не подпадает. Тем же путём проходят `github_pat_`,
`sk-ant-`, `glpat-`, `AIza`, `xoxp-`, токен Telegram, строки `.netrc` и `.pgpass`, `auth` в
`docker config.json`, хеш `htpasswd`.

**A3. Учётные данные во флагах командной строки.**

```sh
printf '%s\n' 'curl -u deploy:S3cretCurlPass https://x' \
              'redis-cli -a S3cretRedisPass ping' | redact_stream
```

Наблюдалось: обе строки без изменений. Правил для `-u`, `-a`, `--password` нет, а такие команды
попадают в снимок из `Cmd` контейнеров, healthcheck'ов и host-скриптов.

**A4. PGP-блок проходит целиком.**

```sh
printf '%s\n' '-----BEGIN PGP PRIVATE KEY BLOCK-----' 'lQOYBGXaBc0BCADHt7t7' \
              '-----END PGP PRIVATE KEY BLOCK-----' | redact_stream
```

Наблюдалось: все три строки без изменений. Шаблоны ждут `-----` сразу после `PRIVATE KEY`, а
здесь идёт ` BLOCK-----`. Для контраста `-----BEGIN OPENSSH PRIVATE KEY-----` маскируется.

**A5. Секрет в ИМЕНИ ключа JSON.**

```sh
printf '%s' '{"sb_secret_CANARY_12345678":"public","safe":"sb_secret_CANARY_12345678"}' | redact_json_deep
```

Наблюдалось: значение замаскировано, **имя ключа осталось**. `map_values` обходит только
значения объектов.

**A6. Расхождение веток: `signature` знает построчный путь и не знает глубокий.**

```sh
printf '%s' '{"v":"https://x.invalid/cb?signature=CANARY_SIG_123"}' | redact_json_deep
printf '%s\n' 'https://x.invalid/cb?signature=CANARY_SIG_123' | redact_stream
```

Наблюдалось: глубокий путь вернул URL нетронутым, построчный замаскировал. Чёрные списки двух
веток разошлись, и рассинхрон ниоткуда не виден. `redact_json_deep` — единственная защита
`containers-summary.json`.

### Класс B — данные уничтожаются

**B1. Одна посторонняя строка съедает весь остаток потока.** Самый тяжёлый дефект.

```sh
printf '%s\n' 'nginx: [emerg] PEM_read_bio_PrivateKey() failed, expected "-----BEGIN PRIVATE KEY-----"' \
              'CONTAINER ID   IMAGE          PORTS' \
              'a1b2c3d4e5f6   postgres:16    0.0.0.0:5432->5432/tcp' \
              'network: proxy-corridor  subnet 172.28.0.0/16' \
              'volume: pgdata 42G' \
              'cron: 0 3 * * * /opt/backup.sh' | redact_stream
```

Наблюдалось: **шесть строк на входе, одна на выходе** — `<REDACTED-PRIVATE-KEY>`. Код возврата
ноль, файл создан, признака отказа нет. Триггер — не обрывок ключа, а любая строка с этим
литералом: сообщение об ошибке, лог, label, README, чужой скрипт. `awk` при незакрытом блоке
остаётся в состоянии «внутри ключа» до конца потока. В коде это названо осознанным решением
(«лучше потерять хвост»), но цена — молча ложный инвентарь.

**B2. Ложные срабатывания на подстроке.**

```sh
printf '%s\n' 'KEYBOARD_LAYOUT=us' 'MONKEY_MODE=on' 'API_URL=https://api.example.com/v1' | redact_stream
```

Наблюдалось: все три значения заменены на `<REDACTED>`. Секрет-слово ищется как произвольная
подстрока имени без границ слова. Домены, хосты, пути и версии — ровно то, ради чего снимается
инвентарь, — попадают под маску и переносятся в `inventory/` как «нет данных».

**B3. Построчный путь ломает валидность JSON.**

```sh
printf '%s\n' '{"Keys": null, "ApiVersion": "1.41"}' | redact_stream | jq .
```

Наблюдалось: `jq` возвращает 5 (ошибка разбора) — незакавыченное значение заменяется на голое
`<REDACTED>`. При этом `dump-snapshot-quirks.md:140` прямо утверждает, что на этом пути «JSON
остаётся валиден». Документация опровергнута замером и подлежит правке вместе с кодом.

**B4. Мёртвый контракт отката.**

```sh
printf 'not json {{{' | redact_json_with_jq; echo $?
```

Наблюдалось: код возврата **0** при пустом выводе. Документация обещает ненулевой код и падение
в построчный откат — этот откат не сработает никогда. Живых вызовов у функции в ревизии нет, но
контракт цитируется в `dump-snapshot-quirks.md` как действующий. Существующий тест «без jq
ненулевой код возврата» проверяет **отсутствие `jq`**, а не его отказ на битом входе — отсюда
зелёный при сломанном контракте.

## 4. Что здесь корень, а что симптом

Заплатки по одному дефекту дадут ещё один зелёный набор при дырявом рубеже. Корней два:

1. **Чёрный список секрет-слов + «значение до первого пробела».** Пока решение строится на
   перечислении имён и наивной границе значения, каждый новый формат секрета — новая дыра, и
   каждое слово вроде `KEY` внутри имени — новое ложное срабатывание.
2. **Две независимые ветки (построчная и JSON) с разными чёрными списками.** Они уже разошлись
   по `signature`, `requirepass`, SQL `PASSWORD '…'` и двоеточию. Любая правка одной должна
   доказуемо отражаться в другой, иначе рассинхрон вернётся.

Решение о том, как это чинить — разделители значений и кавычки, единый источник правил для обеих
веток, границы слова для имён, whitelist для заведомо не-секретных имён (`*_URL`, `*_HOST`,
`*_VERSION`, `*_LAYOUT`), поведение при незакрытом PEM-блоке — принимается в задаче; здесь оно
намеренно не предрешено.

**Одно ограничение всё же жёсткое:** поведение при незакрытом PEM-блоке нельзя оставлять
«съедаем до конца потока». Снимок обязан либо сохранить остальные строки, либо явно отказать с
ненулевым кодом — молчаливая потеря данных при коде возврата ноль запрещена.

## 5. Признак выполненности

- В `tests/test-redact.sh` есть падающий тест на **каждый** из восьми дефектов, и до правки
  набор краснеет, после — зеленеет.
- Прогнан **мутационный** контроль: сломать по одному каждое новое правило и убедиться, что
  набор это ловит. Правило, чью поломку набор не замечает, не считается покрытым.
- Проверены обе ветки на одном и том же входе: построчная и JSON дают согласованный результат.
- `dump-snapshot-quirks.md` приведён в соответствие с замером (утверждение про валидность JSON и
  контракт `redact_json_with_jq` сейчас ложны).
- Прогон `dump-snapshot.sh` на тестовых данных даёт **валидный** `containers-summary.json`.
- Пройдена цепочка проверок персоны: проход замером → фильтр свежим Claude → круг Codex.
  Предмет попадает под порог (безопасность), значит полная форма обязательна.
- Запуск фильтра занесён в `todos/filter-log.md` строкой по схеме — включая чистый исход.

## 6. Чего не делать

- **Не расширять чёрный список и на этом останавливаться.** Это лечение симптома: следующий
  формат токена снова пройдёт.
- **Не ослаблять маскировку ради ложных срабатываний.** Утечка дороже; сужать надо точностью
  (границы слова, whitelist имён), а не удалением правил.
- **Не трогать снимки в `infra/`** — там реальные данные оператора. Все опыты на синтетике.
- **Не коммитить приманки с реалистичными секретами** — только явные `CANARY_…`.
