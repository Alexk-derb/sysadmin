# Evals для /restore-from-backup

> Источник правды для `description` в SKILL.md. Сначала пишутся triggers,
> потом из них формулируется description. При расхождении — описание
> обновляется под triggers.

Скилл закрывает ДВА сценария: (1) реальная потеря данных → восстановление из
снапшота; (2) плановый restore-тест («бэкап без проверенного восстановления —
не бэкап»). Триггеры обоих — ниже.

## ДОЛЖНО триггерить (positive — минимум 3)

- «восстанови из бэкапа»
- «restore из restic»
- «откати базу к вчерашнему снапшоту»
- «достань данные из снапшота за прошлую неделю»
- «я удалил данные, есть же бэкап? восстанови»
- «проверь, что бэкап реально восстанавливается»
- «сделай restore-тест»
- «verify backup» / «restore test»
- «покажи список снапшотов и дай восстановить нужный»
- «прод сломался, накати данные из последнего бэкапа»

## НЕ ДОЛЖНО триггерить (negative — минимум 3)

- «настрой бэкапы на сервере» — это `/setup-backups` (первичная настройка restic/cron/rclone).
- «бэкапы давно не делались, почини расписание» — это `/setup-backups` (настройка), не восстановление.
- «поменяй passphrase репозитория restic» — это `/rotate-secrets` (ротация секрета).
- «перенеси данные на новый сервер» — это `/migrate-server-to-server` (переезд), не restore из снапшота.
- «расскажи, как устроен restic» — вопрос про знания, ответ персоны (knowledge `backup-strategies`).
- «сделай дамп базы прямо сейчас» — это разовый бэкап (часть `/setup-backups` / ручной дамп), не восстановление.

## Edge-cases

- «бэкап не восстанавливается» — это и есть вход в скилл (диагностика restore + честный вердикт), а не сигнал чинить настройку. Если выяснится, что сломан сам стек бэкапов — скилл направит на `/setup-backups`.
- «восстанови сервер целиком» — двусмысленно: restic-снапшот данных восстанавливает этот скилл; полный переезд/пересоздание сервера — `/migrate-server-to-server` или `/bootstrap-new-server`. Уточнить, что именно потеряно.
- «откати после неудачного деплоя» — если откат — это re-deploy предыдущей версии образа, это `/deploy-service` (rollback); если потеряны ДАННЫЕ (БД, тома) — этот скилл. Уточнить «откатить код или восстановить данные?».
- «проверь бэкапы» — может быть `/health-check` (свежесть последнего снапшота, read-only) ИЛИ этот скилл (полноценный restore-тест с реальным восстановлением во временное место). Лёгкая проверка свежести → health-check; «реально ли восстанавливается» → restore-тест здесь.
- «восстанови, но прод не трогай» — валидный вход: восстановление во временное место + сверка БЕЗ промоушена (промоушен = красная зона, требует отдельного type-to-confirm).
