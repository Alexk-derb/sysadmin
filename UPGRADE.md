# UPGRADE — обновление мозга агента

> Как обновиться и что сделать руками при переходе между версиями.
> История изменений — `CHANGELOG.md`. Текущая версия — файл `VERSION`.

## Механизм обновления (канон)

Канон описан в `.claude/agents/references/cold-start.md` (Шаг 5.5 и раздел
«обнови sysadmin»). Кратко:

- **Проверка новых версий:** агент сам, **раз в сутки**, делает `git fetch` и
  сравнивает `VERSION` с последним тегом `vX.Y.Z`. Есть свежее — предложит
  «обнови sysadmin» одной строкой. Никогда не обновляется молча.
- **Применение:** по команде оператора «обнови sysadmin» агент выполняет:

  ```bash
  cd <sysadmin/>
  git fetch origin --tags
  git checkout --detach vX.Y.Z   # последний тег
  ```

  Detached HEAD — это контракт версионированной установки (дерево точно
  соответствует тегу), а не ошибка.
- **Перед обновлением** агент проверяет, что нет локальных правок
  (`git diff-index --quiet HEAD`) — иначе остановится и предложит варианты
  (ветка / откат / адресный коммит выбранных файлов).

## Как код отличает старый конфиг от нового

- Новые конфиги (`agent-config.json`, `infra-config.json`) несут поле
  **`version: "1.0"`** — версию ФОРМАТА файла (не версию мозга). Будущие
  несовместимые изменения формата поднимут это значение, и код будет узнавать
  старый файл по полю, а не по имени.
- Legacy-конфиг `sysadmin-config.json` (до расщепления) поля `version` не имеет
  и распознаётся по имени файла — поддерживается как fallback до миграции
  через `/sysadmin-init`.

## Если что-то пошло не так

- `git status` покажет, что мешает (локальные правки, конфликтные копии).
- Вернуться на предыдущий тег: `git checkout --detach v<прежняя-версия>`.
- Репозиторий в облачной папке (Яндекс.Диск и т.п.) при работе с двух машин
  может побиться — см. предупреждение в `cold-start.md` Шаг 4 (`git fsck`,
  перенос обмена на git remote).
